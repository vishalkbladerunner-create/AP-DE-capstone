1 · Stack: one tool per syllabus topic AP 1–12 · DE 1–12

A modular monolith: one Express app, split into modules by domain. No Redis, no queue, no PostGIS, no microservices, because none of them are taught this semester.

Node.js + ExpressHTTP server, routing, middlewareAP wk 1–4
TypeScripttyped requests, services as classesAP wk 11
Prisma ORMmodels, relations, migrations, seed, transactionsAP wk 5–7
jsonwebtoken + bcryptaccess + refresh tokens, password hashing, RBACAP wk 8–9
PostgreSQLsource of truth: SQL, joins, views, CTEs, ACID, indexesDE wk 1–9
MongoDBread copy for search: CRUD, $set/$inc, aggregationDE wk 10–12
The one rule: PostgreSQL decides, MongoDB copies. Every write and every final "is it really in stock" check goes to PostgreSQL. MongoDB is only read by search, and it can always be rebuilt from PostgreSQL.

5 · Authentication and RBAC AP wk 8–9

Week 8: JWT, hashing, protected routes. Week 9: refresh tokens and role-based access control. The refresh token lives in PostgreSQL through Prisma, never in an external cache.

Access tokenJWT, 15 minutes, signed with JWT_ACCESS_SECRET; payload { sub, role }; sent as Authorization: Bearer
Refresh tokenrandom, 7 days, httpOnly cookie on path /api/v1/auth; only its SHA-256 hash is stored
RefreshToken tableuser_id, token_hash UNIQUE, expires_at, revoked_at; rotated on every refresh
Passwordsbcrypt, 10 rounds, async API only; the hash never leaves AuthService
// middlewares/authenticate.ts
export const authenticate: RequestHandler = (req, _res, next) => {
  const header = req.headers.authorization;
  if (!header?.startsWith('Bearer ')) return next(new AppError(401, 'Log in first'));
  try {
    const p = jwt.verify(header.slice(7), env.JWT_ACCESS_SECRET) as JwtPayload;
    req.user = { id: Number(p.sub), role: p.role };
    next();
  } catch {
    next(new AppError(401, 'Session expired'));
  }
};

// middlewares/authorize.ts
export const authorize = (...roles: Role[]): RequestHandler =>
  (req, _res, next) =>
    roles.includes(req.user!.role) ? next() : next(new AppError(403, 'Forbidden'));
// services/AuthService.ts: refresh with rotation
async refresh(rawToken: string | undefined) {
  if (!rawToken) throw new AppError(401, 'Log in again');
  const hash = sha256(rawToken);
  const row = await prisma.refreshToken.findUnique({
    where: { tokenHash: hash }, include: { user: true } });
  if (!row || row.revokedAt || row.expiresAt < new Date())
    throw new AppError(401, 'Log in again');

  const next = randomToken();
  await prisma.$transaction([
    prisma.refreshToken.update({ where: { id: row.id },
                                 data: { revokedAt: new Date() } }),
    prisma.refreshToken.create({ data: { userId: row.userId,
      tokenHash: sha256(next), expiresAt: days(7) } }),
  ]);
  return { accessToken: signAccess(row.user), refreshToken: next };
}

-- DE wk 6-7: the view every search reads
CREATE VIEW verified_open_pharmacy AS
SELECT p.id, p.name, p.phone, p.lat, p.lng, p.is_24x7
FROM pharmacy p
JOIN operating_hours oh
  ON  oh.pharmacy_id = p.id
  AND oh.day_of_week = EXTRACT(DOW FROM NOW())
  AND CURRENT_TIME BETWEEN oh.open_time AND oh.close_time
WHERE p.status = 'VERIFIED';

-- DE wk 6: missing days
SELECT p.name, d.day
FROM pharmacy p
CROSS JOIN generate_series(0, 6) AS d(day)
LEFT JOIN operating_hours oh
  ON oh.pharmacy_id = p.id AND oh.day_of_week = d.day
WHERE p.status = 'VERIFIED' AND oh.id IS NULL;
-- DE wk 7: CTE + correlated NOT EXISTS
WITH expiring AS (
  SELECT c.pharmacy_id, c.license_number, c.expiry_date
  FROM credential c
  WHERE c.expiry_date BETWEEN CURRENT_DATE
                          AND CURRENT_DATE + INTERVAL '30 days'
)
SELECT p.name, e.license_number, e.expiry_date
FROM expiring e
JOIN pharmacy p ON p.id = e.pharmacy_id
WHERE NOT EXISTS (
  SELECT 1 FROM credential c2
  WHERE c2.pharmacy_id = e.pharmacy_id
    AND c2.expiry_date > e.expiry_date);

-- DE wk 4: GROUP BY + HAVING
SELECT s.pharmacy_id, COUNT(*) AS expired_holds
FROM hold h JOIN stock_item s ON s.id = h.stock_item_id
WHERE h.status = 'EXPIRED'
  AND h.expires_at >= DATE_TRUNC('week', NOW())
GROUP BY s.pharmacy_id
HAVING COUNT(*) > 5;
10 · The hold: one ACID transaction AP wk 7 · DE wk 8

Two patients tap Hold on the last unit at once. The decrement only happens while quantity is at least 1, so PostgreSQL itself decides the one winner.

// services/HoldService.ts
async placeHold(patientId: number, stockItemId: number) {
  if (await prisma.hold.count({ where: { patientId, status: 'ACTIVE',
                                         expiresAt: { gt: new Date() } } }))
    throw new AppError(409, 'You already have an active hold');

  const hold = await prisma.$transaction(async (tx) => {
    // 1. lazy expiry: old holds on this item give their units back
    const expired = await tx.hold.updateMany({
      where: { stockItemId, status: 'ACTIVE', expiresAt: { lt: new Date() } },
      data:  { status: 'EXPIRED' } });
    if (expired.count) await tx.stockItem.update({ where: { id: stockItemId },
      data: { quantity: { increment: expired.count } } });

    // 2. take one unit only if one is left
    const took = await tx.stockItem.updateMany({
      where: { id: stockItemId, quantity: { gte: 1 } },
      data:  { quantity: { decrement: 1 } } });
    if (took.count === 0) throw new AppError(409, 'Just missed it'); // ROLLBACK

    // 3. record it
    return tx.hold.create({ data: { stockItemId, patientId, status: 'ACTIVE',
      expiresAt: new Date(Date.now() + 30 * 60_000) } });
  });                                                              // COMMIT

  await this.copy.adjust(stockItemId, -1);   // Mongo $inc, after commit
  return hold;
}
Atomicitydecrement and hold insert commit together or not at all; a thrown AppError rolls both back
ConsistencyCHECK quantity ≥ 0 means the database refuses a negative count even if code is wrong
Isolationthe UPDATE row-locks the stock row; the second transaction waits, re-reads, finds 0, updates 0 rows
Durabilityonce COMMIT returns, the hold survives a crash; only then is the patient told "reserved"
Canceltransaction: ACTIVE → CANCELLED and quantity + 1
CollectACTIVE → COLLECTED; quantity unchanged, the unit left the shelf

// middlewares/errorHandler.ts
export const errorHandler: ErrorRequestHandler = (err, _req, res, _next) => {
  if (err?.code === 'P2002') err = new AppError(409, 'Already exists');
  if (err?.code === 'P2025') err = new AppError(404, 'Not found');
  if (err instanceof AppError)
    return res.status(err.status).json({ error: { status: err.status,
      message: err.message, details: err.details } });
  console.error(err);                                  // stack stays on the server
  res.status(500).json({ error: { status: 500, message: 'Something went wrong' } });
};

14 · The event loop: rules that keep one thread fast AP wk 10

Node runs your JavaScript on one main thread. While it waits on PostgreSQL, MongoDB or bcrypt, it serves other requests. Anything synchronous and slow makes every user wait.

bcrypt async onlyawait bcrypt.hash() runs in the libuv thread pool; hashSync blocks everyone
No sync fs in requestsfs.promises in the seed script; no readFileSync in any handler
Paginate everythingPrisma take / skip, default 20, max 50
Let SQL do the workfilter, join and sort in the query; never load a table and loop in JS
Parallel when independentPromise.all for the three compliance reports, not three awaits in a row
Short transactionsno network calls inside $transaction; the Mongo copy happens after commit
