1 · Stack and rendering: client-rendered on purpose

Results change every minute and nobody needs an emergency search page in Google, so there's nothing to pre-build (no SSG) and no SEO reason for server rendering (no SSR). A small Vite SPA loads once and then only moves JSON.

React 18 + TypeScriptfunction components and hooks only; shared types for API responses
Vitedev server with /api proxy to localhost:4000; production build to dist/
React Router v6createBrowserRouter, nested layouts, loaders not used
TanStack Queryevery piece of data that came from the API: caching, refetch, retries
React Hook Form + Zodforms with the same rules the API validates
Tailwind CSSmobile-first utility classes, one theme file for colours

6 · State: four kinds, kept in four places

The most common React mistake is putting API data into useState or a global store. Each kind of state has a different lifetime, so each gets its own tool.

Server statecame from the API and can go stale
  • TanStack Query cache
  • search results, holds, stock, pending list
Auth statewho is logged in
  • AuthContext + useReducer
  • user, accessToken, status
  • LOGIN, TOKEN_REFRESHED, LOGOUT
URL stateshould survive reload and be shareable
  • useSearchParams
  • ?medicine=, ?area=, admin tab
UI statelives only on this screen

Access token lives in memory only, inside AuthContext. On a page reload the app calls POST /auth/refresh once; the browser sends the httpOnly cookie, and the user is back without typing anything. Logout clears the context and the whole query cache so no one else's data stays on screen.

8 · API client: one place for tokens, refresh and errors

Every request goes through apiFetch. It adds the token, turns error bodies into one ApiError type, and on a 401 runs a single refresh that every waiting request shares.

1. Build the requestbase /api/v1, JSON headers, credentials: 'include', Bearer token if logged in
2. Got 401?start one refresh (or join the one already running), then retry the request once
3. Refresh faileddispatch LOGOUT, clear the cache, send to /login with the current page saved
4. Other errorsthrow ApiError(status, message, details); the component decides what to show
// api/client.ts
let refreshing: Promise<string | null> | null = null;   // shared by every 401

async function refreshOnce() {
  refreshing ??= fetch('/api/v1/auth/refresh', { method: 'POST', credentials: 'include' })
    .then(r => (r.ok ? r.json() : null))
    .then(body => { const t = body?.accessToken ?? null; auth.setToken(t); return t; })
    .finally(() => { refreshing = null; });
  return refreshing;
}

export async function apiFetch<T>(path: string, init: RequestInit = {}, retried = false): Promise<T> {
  const res = await fetch('/api/v1' + path, {
    ...init, credentials: 'include',
    headers: { 'Content-Type': 'application/json',
               ...(auth.token ? { Authorization: `Bearer ${auth.token}` } : {}),
               ...init.headers },
  });
  if (res.status === 401 && !retried && !path.startsWith('/auth/')) {
    const token = await refreshOnce();
    if (token) return apiFetch<T>(path, init, true);
    auth.logout();                                        // clears cache, goes to /login
  }
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new ApiError(res.status, body.error?.message ?? 'Something went wrong', body.error?.details);
  }
  return res.status === 204 ? (undefined as T) : res.json();
}
9 · Forms and validation

React Hook Form keeps typing fast; Zod checks the same rules the API checks, so most mistakes are caught before a request is sent. The API still validates everything.

// lib/schemas.ts
export const onboardingSchema = z.object({
  name:          z.string().min(3),
  address:       z.string().min(10),
  area:          z.string(),
  lat:           z.number().min(-90).max(90),
  lng:           z.number().min(-180).max(180),
  phone:         z.string().regex(/^[6-9]\d{9}$/, 'Enter a 10-digit mobile number'),
  licenseNumber: z.string().min(5),
  issueDate:     z.coerce.date(),
  expiryDate:    z.coerce.date(),
}).refine(d => d.expiryDate > new Date(),
          { path: ['expiryDate'], message: 'Licence has already expired' });

14 · Testing: the parts that would hurt if they broke

Vitest + React Testing Library. Test behaviour a user would notice, not implementation details.

api/client.tstwo 401s at once trigger exactly one refresh; a failed refresh logs out
RequireRolePATIENT on /admin sees the 403 page; logged-out user is sent to /login and back
useCountdownwith fake timers: label counts down, isExpired flips at 0, interval cleared on unmount
HoldButtondisabled while pending; 409 shows "Just missed it" and refetches results
SearchPageloading, empty and error states each render their own UI
Formsexpired licence date is rejected before submit; server 400 lands on the right field
Browser → React Router → page → custom hook → TanStack Query cache → apiFetch → /api/v1 (Vercel rewrite) → Express.
Same REST contract as the backend: no GraphQL, no WebSockets, no SSR. Role checks here are convenience; the backend's RBAC middleware is the real boundary.
